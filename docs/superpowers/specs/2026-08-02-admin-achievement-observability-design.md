# 管理员成就观测页设计

日期：2026-08-02

## 目标

将 `/practicum/achievements` 改为角色化页面：学生继续查看个人成就；管理员在同一路由查看本实训室学生的完成情况，不再出现“成就仅向学生视图开放”的提示或要求切换身份。

本切片只解决“管理员观察学生学习完成情况”的 P0 能力。它不新增勋章规则、邀请、课堂公告、资源导入或其他缺口模块。

## 用户与权限

| 用户 | 可见内容 | 数据权限 |
| --- | --- | --- |
| OWNER | 班级概览、六维能力图、完成率排名、学生完成列表 | 仅当前实训室成员的汇总与明细 |
| STUDENT | 原有个人技能、勋章与奖励时间线 | 仅个人成就数据 |
| TEACHER / MENTOR | 本切片保持既有受限状态 | 不新增访问范围 |

管理员点击学生头像或姓名时，进入既有 `/practicum/member-data/:memberId`。该详情页继续由服务端对象权限保护；学生直接访问该路由必须得到 403/无权限状态。

## 页面结构

### 管理员视图

1. 顶部指标条：学生数、平均完成率、已完成任务数、待批阅数。
2. 数据概览区：左侧为 SVG 六边形雷达图，展示全班六项技能维度的平均掌握度；右侧为完成率排行榜，显示排名、头像、姓名、完成率和已评分任务数。
3. 学生完成情况：可扫描的表格/列表，显示头像、姓名、完成率、完成任务数、已评分任务数和进入详情入口。头像与姓名均可点击。
4. 状态处理：加载、空数据、加载失败和无权限均使用现有 `PracticumStatePanel`，不回退到 store 或 seed 数据。

### 学生视图

保留当前个人成就页面，包括个人技能矩阵、勋章墙、奖励时间线和“继续完成任务”操作；不展示任何其他学生数据。

## 数据与接口

复用已有服务端接口，不复制目标站接口：

- `GET /api/practicum/analytics/members?roomId=<currentRoomId>`：返回成员完成率、已评分任务数等排名数据。
- `GET /api/practicum/analytics/members/:memberId?roomId=<currentRoomId>`：供成员详情页展示计划分解和技能明细。

为雷达图补充的班级六维数据必须由服务端聚合返回，或由第一条接口返回的成员技能数据计算。前端不得根据 `usePracticumStore`、localStorage 或匿名 seed 构造管理员统计。

## 交互与视觉

- 雷达图使用语义化 SVG 绘制六边形网格和数据区域，具备可读的维度标签与文本摘要，不依赖图表库。
- 排名和完成情况列表采用工作台的轻量表格样式；头像使用稳定的姓名首字/编号占位，不引入外部个人头像资源。
- 桌面端并列显示雷达图与排名；窄屏改为纵向堆叠，学生列表保留可点击行且不产生水平滚动。
- 不新增侧边栏一级入口；继续使用学生“成长数据”中的成就链接与现有管理员直接路由访问方式。

## 验收与测试

新增 Playwright 覆盖：

1. OWNER 打开 `/practicum/achievements` 可见管理员概览、雷达图、排名和完成列表，且不出现学生专属提示。
2. OWNER 点击学生头像或姓名进入对应成员数据详情。
3. STUDENT 打开同一路由仍可见个人成就，且不会看到班级成员数据。
4. 成员分析接口返回空数据或失败时，管理员页展示正确状态，不展示本地替代数据。
5. 390px 视口下管理员页面无水平滚动。
