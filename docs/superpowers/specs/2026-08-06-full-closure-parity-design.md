# 实训工作台高标准闭环设计

## 目标

将当前前端入口从“页面可进入”提升为可验收的真实业务闭环。每个能力只有在服务端业务逻辑、数据库持久化、角色与实训室隔离、真实页面入口、状态处理、刷新恢复、BDD、TDD 和 Playwright 用户路径均有证据时，才标记为完成。

本阶段优先完成学生学习与教师审核闭环，后续按独立切片推进教师工作台、通知进度、成员实训室、资源数据、模板比赛。

## 核心用户路径

1. 教师发布计划或班级任务。
2. 学生看到服务端任务，进入活动详情，保存草稿并提交版本。
3. 学生刷新或重新登录后仍能看到提交状态和版本。
4. 教师在审核队列查看证据，填写退回反馈或评分。
5. 学生收到退回或评分结果，退回后修改并生成新版本。
6. 进度和通知反映同一份服务端事实。

## 完成门槛

- API：输入校验、幂等、状态机、权限和 room/class scope。
- 数据：提交版本不可变，评分和反馈留痕，刷新后可读。
- UI：loading、empty、error、forbidden、success、重复提交防护。
- 入口：侧栏、任务列表、计划页和通知中的链接均指向真实页面。
- 验证：每个切片有 BDD 场景、先 RED 后 GREEN 的 API/E2E 证据和 Playwright 用户路径。
- 响应式：390px 与桌面视口无横向溢出、遮挡或不可点击按钮。

## 非目标

本阶段不修改 Prisma schema、迁移、数据库连接、认证实现、部署脚本或 LearnEC 视觉基线。已有 localStorage 仅可作为明确标注的演示降级，不能覆盖服务端事实。
