# 教学练评闭环设计

## 目标

第一阶段交付一条可由不同真实角色在前端完成并在刷新后保留的数据链：教师在获授权的实训室创建班级、添加学生、发布任务；学生完成并提交成果；教师退回或评分；学生可按反馈重提；教师和学生都能查看最终成绩、版本历史和审计记录。

本设计不把页面存在或接口存在判定为完成。每个写操作必须落在 PostgreSQL，并具有角色边界、可追溯事件和 Playwright 真实会话验收。

## 范围与阶段

### 第一阶段：班级任务闭环

- 现有 `OWNER` 管理组织、实训室和教师的可访问范围；不创建新的平台管理员入口。
- `TEACHER` 在已授权实训室创建并管理自己的班级，添加或移除学生。
- 教师在班级详情页选择已发布计划，配置任务名称、要求、开放时间、截止时间和迟交规则，发布后为每个学生生成任务。
- 学生仅能查看当前组织、实训室和班级中已发布且可用的任务；草稿是本地辅助数据，提交版本是服务端事实来源。
- 教师通过班级批阅队列查看学生提交，按量规退回或评分；退回必须填写反馈，重提追加新版本，评分写入不可覆盖的成绩历史。
- 班级详情展示完成率、待批数量、未交人数和平均分；学生任务详情展示状态、反馈、版本与成绩。
- 组织上下文切换必须改变班级、任务、资源和报表的查询范围，且只展示已授权范围。
- 审计记录建班、成员变更、发布、提交、退回、评分和导出；记录操作者、时间、组织、实训室、班级和对象标识。

### 第二阶段：可见的组织与资源中心

- 组织与实训室管理页：OWNER 可创建、编辑并切换组织及实训室，授予教师范围。
- 资源中心：OWNER 与有授权的教师可创建、编辑、发布、撤回和筛选资源；学生只可读取当前实训室中已发布的资源。
- 资源先支持受控链接及元数据；文件上传、对象存储、病毒扫描和受控下载作为下一切片，不伪装为已支持的能力。

### 第三阶段：平台监督与运维

- 独立平台管理入口及 `SUPERVISOR`（监督管理员）角色后置实现。
- `SUPERVISOR` 只读查看跨组织健康状态、审计、失败率和容量趋势，不得修改学校、班级、任务、成绩或学生数据。
- 运维页展示应用与数据库健康、近 24 小时写操作量、失败请求、待批积压和最近异常；设置告警阈值与响应记录。
- 配置 PostgreSQL 定时备份、保留策略、加密存储和季度恢复演练。恢复演练成功才可标记为已完成。

## 角色与权限

| 角色 | 第一阶段权限 |
|---|---|
| OWNER | 管理已授权组织和实训室；为教师授予范围；管理计划；查看本范围班级、任务、成绩和审计。 |
| TEACHER | 仅在授权实训室创建自己的班级；维护班级成员；发布和管理本班任务；批阅本班学生成果。 |
| STUDENT | 仅查看自己的班级任务、资源、提交版本、反馈和成绩。 |
| SUPERVISOR | 第一阶段不存在；第三阶段只读跨组织运维和审计。 |

任何接口均先验证组织、实训室、班级与角色范围，再读取目标记录。越权资源按不存在处理，避免泄露标识与数据。

## 架构决策

Prisma/PostgreSQL 是班级、任务、提交、评分、成绩、报表与审计的唯一事实来源。当前 `practicum-repository.ts` 和浏览器 `localStorage` 中的兼容数据不得参与第一阶段的任务发布、提交、退回或评分状态机。

`Plan` 与课程目录继续作为可复用教学内容。`Class`、`ClassEnrollment`、`PlanAssignment`、`StudentTask`、`Submission`、`SubmissionVersion`、`Grade`、`GradeRevision` 和审计事件构成班级任务链。每个 `StudentTask` 绑定一个学生和一个计划活动；每次重提交都追加 `SubmissionVersion`，不覆盖既有版本。

## 状态与失败规则

任务状态为 `AVAILABLE -> IN_PROGRESS -> SUBMITTED -> RETURNED -> SUBMITTED -> GRADED`。截止时间且不允许迟交时，学生不可提交；已评分任务不可修改；退回必须有非空反馈；评分必须完成必评量规项且分数在允许范围内。

所有写操作使用 CSRF 校验、事务和幂等键。重复发布、重复加入、重复提交不得生成重复数据。班级、任务、提交和成绩页面均提供 loading、empty、forbidden、error 和 success 状态。

## 可见前端入口

- `/practicum/classes`：教师班级列表与创建入口。
- `/practicum/classes/:classId`：成员、已发布任务、创建任务、班级概览与成绩入口。
- `/practicum/classes/:classId/tasks/:assignmentId`：教师任务详情、发布状态和批阅入口。
- `/practicum/tasks`：学生待完成任务，只读取 Prisma 任务实例。
- `/practicum/reviews`：教师本班待批阅队列；详情通过任务和提交 ID 读取服务端版本。
- `/practicum/data-center`：OWNER/TEACHER 在授权范围查看班级完成率、未交和成绩，并导出。

## 验收

Playwright 使用独立 OWNER、TEACHER、STUDENT 会话和干净测试数据库执行以下路径：

1. OWNER 授予教师实训室范围。
2. TEACHER 创建班级并添加 STUDENT。
3. TEACHER 为班级创建并发布任务。
4. STUDENT 刷新页面后看到任务，提交第一个版本。
5. TEACHER 刷新页面后退回并填写反馈。
6. STUDENT 刷新后看到反馈，重提第二个版本。
7. TEACHER 评分，STUDENT 刷新后看到成绩。
8. OWNER/TEACHER 在班级报表看到对应完成与成绩数据，并可查看审计事件。
9. 无关教师与学生访问该班级、任务、提交或导出接口时被拒绝。

验证门槛为：相关 API 测试、真实角色 Playwright 流程、类型检查、生产构建均通过；不通过则保持未完成状态。
