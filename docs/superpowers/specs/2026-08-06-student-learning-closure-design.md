# 学生真实学习闭环设计

**日期：** 2026-08-06

**目标：** 将学生端从本地 Store/服务端兼容混合模式，收敛为可刷新、可跨设备、可审计的服务端学习闭环。

## 范围

本期只处理学生主链路：已发布计划、任务列表、活动详情、学习位置、草稿、提交版本、教师退回、再次提交、评分结果和刷新恢复。保留现有 LearnEC 视觉改动，不重做无关页面。

本期不实现：教师独立工作台、成员邀请、虚拟组、资源对象存储、比赛模板和远程部署。这些作为后续独立切片，避免多个角色共享文件同时变更。

## 用户结果

学生登录后只能看到被分配到当前实训室的任务。任务显示类型、标题、来源、发布时间、截止时间和当前状态。学生进入活动后可以看到前置条件、说明和提交区；草稿保存到服务端，提交生成不可变版本。教师退回时必须提供反馈，学生可以在 `RETURNED` 状态修改并生成新版本。评分后学生看到总分、评分反馈和评分时间。刷新、重新登录和更换浏览器后，状态保持一致。

## 数据与权限

- PostgreSQL 的 `PlanAssignment`、`StudentTask`、`Submission`、`SubmissionVersion`、`Grade`、`GradeRevision` 和学习审计记录作为业务来源。
- 学生只能读取自己的 `StudentTask`、自己的提交版本和自己的评分；教师只能访问被分配班级；OWNER 可以访问授权实训室。
- 所有写操作校验当前状态、角色、实训室和对象归属。
- 提交使用幂等键；同一学生同一任务同一幂等键只能产生一个结果。
- 不新增 Prisma 破坏性操作，不使用 `migrate reset`、`db push` 或数据库清空。

## 页面适配

- `/practicum/tasks` 使用服务端任务列表作为唯一业务列表，保留 loading、empty、error、forbidden、分页和重试。
- `/practicum/activities/[activityId]` 优先通过 `StudentTask` 读取状态、草稿、版本和反馈；旧 Store 只允许作为没有服务端任务时的明确迁移提示，不得覆盖服务端结果。
- `/practicum/learn/[planId]` 的目录和学习进度由服务端任务状态驱动，继续学习入口必须指向当前可学习任务。
- 所有主要操作使用稳定 `data-*` 标记，桌面和 390px 移动端均验证无横向溢出。

## 状态与错误

任务状态至少覆盖 `LOCKED`、`AVAILABLE`、`IN_PROGRESS`、`SUBMITTED`、`RETURNED`、`GRADED` 和 `CLOSED`。页面需要把非法状态转换显示为可理解的反馈，不通过隐藏按钮绕过服务端规则。网络失败、过期会话、版本冲突、空反馈、空提交和重复点击都要有可见结果。

## 验收门槛

只有同时具备 API、服务端持久化、角色隔离、状态转换、刷新恢复、BDD、TDD/API 和 Playwright 用户路径证据，学生闭环才从 `PARTIAL` 提升为 `PASS`。typecheck、build、相关 Playwright 和 `git diff --check` 必须有本轮输出；部署不属于本期完成条件。
