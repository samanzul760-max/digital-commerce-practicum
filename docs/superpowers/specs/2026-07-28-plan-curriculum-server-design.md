# 计划目录树服务端闭环设计

## 目标

让 OWNER 在计划编辑页管理三级课程目录和活动时，页面读取与所有写入都以服务端数据为准。刷新、重新登录或其他浏览器访问同一计划时，结果必须一致；页面不得回退到 `localStorage` 或前端 store 保存目录树。

该切片对应已观察到的参考产品能力：管理者在计划内维护分层目录，并在中间层添加活动。参考观察只用于确定业务能力，不复制其品牌、文案、素材或接口。

## 范围

- 保留现有计划编辑页面和稳定 `data-*` 选择器。
- 为目录节点和活动增加服务端读取、创建、重命名、删除、排序及活动配置保存。
- 每次目录树写入均校验 OWNER、实训室归属、计划状态和计划版本。
- 服务端持久化到现有单机仓库；该实现不把单机 JSON 文件称为多实例生产数据库。
- 页面覆盖 loading、empty、error、forbidden、版本冲突、重复点击和刷新保持。

## 不在范围内

- TEACHER 与 MENTOR 工作台。
- 学生学习进度、草稿提交、成员、通知和资源模块的整体迁移。
- 多实例数据库、Redis、CSRF 和审计日志。这些继续保留在安全审计差距中。

## 接口与数据

计划详情继续返回 `plan`、`nodes` 与 `activities`。新增的目录写接口遵循以下原则：

- `POST /api/practicum/plans/:planId/nodes`：创建目录或活动节点，携带父节点、标题、排序位置与 `version`。
- `PATCH /api/practicum/plans/:planId/nodes/:nodeId`：重命名、排序或保存活动配置，携带当前 `version`。
- `DELETE /api/practicum/plans/:planId/nodes/:nodeId`：删除允许删除的节点及其未产生提交的后代，携带当前 `version`。

每次成功写入返回新的完整计划快照及递增后的 `version`。重复请求以 `Idempotency-Key` 返回首次结果，不能创建重复节点。版本不匹配返回稳定的 `PLAN_VERSION_CONFLICT`，无权访问返回 `PLAN_FORBIDDEN`。

`CurriculumNode` 保持 `planId`、`parentId`、`level`、`title`、`sort` 与可选 `activityId`。服务端负责校验层级：一级节点没有父节点，二级节点属于一级节点，活动节点属于二级节点。

## 页面数据流

编辑页初次加载只请求计划详情。请求期间显示 loading；无节点时显示空状态；请求失败显示可重试错误；无权访问显示 forbidden。成功后把服务端快照作为唯一渲染源。

OWNER 提交一个目录或活动操作时，按钮立即禁用。页面带当前版本和幂等键调用接口，成功后替换为响应快照；冲突时重新获取快照并提示用户重试；失败时保留最后确认的服务端快照，不能使用本地数据伪造成功。刷新后重新请求详情并呈现同一服务端状态。

STUDENT 只能读取已发布计划，且不能访问编辑页或目录写接口。

## 验收与证据

BDD 覆盖创建、重命名、排序、删除、活动配置、空态、加载、失败、越权、版本冲突、重复提交和刷新。

API 测试验证对象归属、层级校验、状态限制、幂等和版本冲突。Playwright 用 OWNER 的桌面端与移动端完成目录维护并刷新确认；STUDENT 直接访问编辑 URL 必须被拒绝。通过 typecheck、build、相关 API/E2E 后，才可将“计划”矩阵行从 `PARTIAL` 收窄；只有本切片全部证据齐全才能更新该行的对应子能力为 `PASS`。
