# 管理员开通与独立登录设计

## 目标

提供独立的 `/practicum/login` 登录入口。未认证用户不能查看工作台内容；首次部署时，管理员可在登录页开通一个管理员账号，密码仅通过浏览器提交，服务端只在被 Git 忽略的数据目录中保存 scrypt 摘要。

## 方案

采用一次性管理员开通。与把密码写入源码或允许公开注册任意管理员相比，它不会把凭据带入 Git 历史，并在成功开通后关闭开通接口。

`/practicum/login` 初次加载查询开通状态。未开通时显示简洁的管理员开通表单；开通成功后立即建立 HttpOnly 会话并进入 `/practicum`。开通已完成时只显示登录表单。登录中的按钮禁用，失败显示通用错误，不回显密码。

## 服务端边界

自定义账号保存在 `.data/auth-users.json`，该目录已被 Git 忽略。`POST /api/auth/bootstrap-owner` 仅在尚无自定义管理员时允许执行一次，校验账号、显示名和密码长度，创建 `OWNER` 用户并返回会话。重复请求返回稳定的 `BOOTSTRAP_ALREADY_COMPLETED`，且绝不返回密码、盐或摘要。

部署脚本必须保留远程 `.data/`，否则账号和会话会在下一次发布时被删除。

## 验收

BDD-AUTH-006 验证首次开通、登录和刷新。BDD-AUTH-007 验证再次开通被拒绝。BDD-AUTH-008 验证未认证用户被导向独立登录页。桌面端和 390px 移动端均通过 Playwright 验收。
