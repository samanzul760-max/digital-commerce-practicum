# 高标准闭环实施计划

## 工作规则

- 每项先写最小 BDD/API 测试并运行一次 RED，再写生产代码。
- 子任务使用不重叠文件范围；共享 composable、服务端公共函数和数据库相关改动由主线程顺序处理。
- 每项 GREEN 后跑相关 Playwright，再审查 diff；未满足完成门槛不得把矩阵标为 COMPLETE。
- 保留现有 LearnEC/OpenDesign 未提交修改，不做整仓回滚。

## 切片

1. 学生活动详情：服务端任务详情、草稿/提交、刷新恢复、退回重提、版本和评分展示。
2. 教师审核：审核队列、证据详情、退回反馈、评分、版本历史、批改下一个和学生禁入。
3. 进度与通知：服务端唯一来源、已读状态、退回/评分通知和跨刷新恢复。
4. 教师工作台：班级、作业、公告、课堂执行和班级统计真实入口。
5. 成员与实训室：虚拟组、邀请、申请审批、角色调整和生命周期状态。
6. 资源与平台能力：资源上传、数据中心、审计日志、错误/空状态和导出。
7. 模板与比赛：模板选择、复制发布、比赛入口、权限和发布门槛。
8. 最终验收：功能矩阵、BDD/TDD 证据、桌面/移动 Playwright 闭环、typecheck、build 和 diff 检查。

## 当前批次验收

第一批只允许修改：

- `pages/practicum/activities/[activityId].vue` 及其专属测试；
- `pages/practicum/reviews/index.vue`、`pages/practicum/submissions/[submissionId].vue` 及其专属测试。

共享 API composable 若需修改，必须由主线程在两个页面批次完成后顺序处理，避免多个智能体同时写同一文件。
