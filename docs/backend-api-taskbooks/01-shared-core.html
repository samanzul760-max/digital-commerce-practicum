LearnEC / 后端任务包 01

共享后端核心

管理员端和学生端共同使用的一套真实教学数据、权限与状态机。目标不是做两个页面，而是让一次发布、一次提交、一次评分在同一条可追溯数据链中闭环。

核心边界

唯一事实来源账号、班级、工单、提交、成绩、通知和审计全部由 PostgreSQL + Prisma 保存。浏览器不保存业务事实。
两种新角色ADMIN配置、发布、批阅、分析。STUDENT学习、实训、提交、查看本人结果。
范围隔离每一次读取和写入都先校验用户、实训室、班级和对象归属；改 URL 不能看到他人数据。
兼容迁移旧 /api/practicum/* 保持可用，直到等价的新 Prisma API 通过回归测试后才废弃。

共享实体

领域实体解决什么问题
身份User、UserRoleGrant、AuthSession账户状态、登录会话、角色授权、CSRF 绑定。
教学范围Organization、TrainingRoom、Cohort、Class、ClassEnrollment确定用户属于哪个组织、实训室和班级。
成员RoomMember、VirtualGroup、JoinApplication、MemberInvite学生加入、分组、邀请、申请和审批历史。
内容ResourceCatalogItem、WorkOrderTemplate、TaskSection、TaskQuestion、SandboxSpec可复用的课程资源、题目、沙盘步骤、量规。
交付PlanAssignment、StudentTask、TaskDependency发布时冻结任务，并按班级/分组为学生建立独立任务。
学习与成果TaskEvent、SandboxSnapshot、SubmissionVersion、SubmissionPart记录学习过程、操作证据和不可改写的提交版本。
批阅与运营Grade、GradeRevision、Notification、AuditEvent评分修订、通知到达和管理员动作审计。

四条关键流程

1. 发布：管理员验证模板、权重、时间、范围和依赖关系，创建任务快照并为符合条件的学生生成 StudentTask。
2. 学习：学生只能读取自己的任务快照，保存草稿、事件和沙盘证据；模板后续修改不影响已发任务。
3. 提交与批阅：提交生成不可变 SubmissionVersion；管理员基于当前版本评分或退回，写入 GradeRevision、TaskEvent 和 AuditEvent。
4. 数据：学生个人数据与管理员班级数据从任务、提交和成绩聚合，导出由服务器生成文件。
StudentTask: LOCKED -> AVAILABLE -> IN_PROGRESS -> SUBMITTED
             SUBMITTED -> RETURNED -> SUBMITTED -> GRADED
             AVAILABLE / IN_PROGRESS -> CLOSED

必须由后端保证的事情

权限未登录为 401；角色不符为 403；跨实训室或跨班级对象按统一合同拒绝。
幂等发布、邀请、创建账号、提交、导出等请求带 Idempotency-Key，重复点击返回原结果而不是重复写入。
版本冲突编辑模板、保存任务和评分携带 version 或 expectedVersion，旧页面写入返回 409。
审计账号变更、发布、撤回、退回、评分、赛考结果发布、导出均追加审计事件。
禁止事项：不能用 localStorage 生成成绩、提交、权限或待办；不能让赛考单独拥有一套成绩和提交表；不能把旧 OWNER 判断继续写进新 API。

正式接口边界

/api/auth/*              身份与会话
/api/admin/*             管理员/教师端业务
/api/center/*            学生端业务
/api/practicum/*         旧接口兼容层，迁移完成后才标记废弃

共享核心完成的验收路径：管理员发布 -> 学生开始与提交 -> 管理员批阅 -> 学生查看成绩 -> 管理员导出班级成绩。

公开调研依据

这些结论来自高校公开实验室页面和采购需求，说明成熟平台的共同底座是“教学管理 + 受控实训 + 过程评价”，不是模拟商城页面。它们是能力基线，不代表 LearnEC 已实现。

任务书与资源每项实训应有目标、前置知识、步骤、练习、题目、量规和受控场景，并在发布时冻结。
共同记录课堂、公告、学习事件、草稿、提交版本、评分和通知必须在同一条数据链上。
双轨评价系统可判的部分自动评分；需要判断的证据由教师按量规评分，两个分数和修改历史可追溯。
领域包跨境、数据运营、客服、直播等只提供资源、规则与量规包，不能复制一套账号、成绩或权限数据。

来源：西昌学院、上海工商职业技术学院、深圳大学、跨境电子商务专业实训室采购要求、上海工商职业技术学院直播电商采购要求。

对标验收矩阵

“对标”不是只让页面看起来相似，而是功能入口、教学流程、数据可信度和移动端体验都能验收。

维度必须证明
功能入口正确角色能从菜单或路由找到能力；未完成能力诚实说明，不伪造成功。
教学闭环管理员配置并发布，学生学习、实训、提交，管理员批阅，学生收到结果。
过程证据事件、尝试、快照、提交版本、反馈和评分修订可在授权范围追溯。
课堂与数据班级、公告、授课、任务、通知和学情在同一数据链；指标可回钻到原始记录。
专业场景跨境、数据、客服、直播、赛考复用同一身份、任务、提交和成绩模型。
体验质量无死链、角色权限正确、390px 无横向溢出，且核心路径有真实数据 E2E 证据。
完成定义：页面能打开或接口返回 200 都不算完成；必须同时有入口、真实数据流程、权限/异常测试和浏览器验收证据。
