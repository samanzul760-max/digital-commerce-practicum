# 资源、通知、数据与审计

功能: 受实训室和角色约束的资源、通知、数据与审计

  场景: BDD-RDA-001 管理员只能读取当前实训室的数据总览
    假如 管理员已登录且拥有实训室 room-001 的访问权限
    当 管理员请求 room-001 的数据总览
    那么 服务端返回该实训室的统计、计划完成情况和最近审计摘要
    并且 不返回管理员无权访问的实训室的数据

  场景: BDD-RDA-002 学生不能读取管理数据或审计记录
    假如 学生已登录并属于 room-001
    当 学生请求 room-001 的数据总览或审计记录
    那么 服务端返回稳定的 403 错误码
    并且 响应不包含其他成员、计划或审计事件

  场景: BDD-RDA-003 通知只能由目标用户标记为已读
    假如 学生有一条属于自己的未读通知
    当 该学生将通知标记为已读
    那么 服务端持久化已读状态
    并且 写入 trainingRoomId、操作者、实体和事件类型均完整的 AuditEvent
    并且 其他角色不能通过通知标识修改该通知

  场景: BDD-RDA-004 资源页面只显示服务端允许的资源结果
    假如 用户进入资源中心
    当 服务端返回资源列表或拒绝访问
    那么 页面只显示服务端返回的资源或受限状态
    并且 服务端失败时页面显示错误状态
    并且 页面不使用 localStorage、store 或静态业务数据作为回退

  场景: BDD-RDA-005 数据中心提供受限的钻取和审计查询
    假如 管理员选择了当前实训室
    当 管理员打开计划、成员钻取或按事件类型筛选审计记录
    那么 每个结果都只属于当前实训室
    并且 查询参数会限制页大小和时间游标
    并且 空结果显示为空状态而不是示例数据

  场景: BDD-RDA-006 通知页面只确认服务端已读结果
    假如 用户在通知页点击未读通知
    当 已读请求成功
    那么 页面更新该条服务端通知的已读状态
    当 已读请求失败
    那么 页面重新加载服务端通知并显示失败状态
    并且 不把已读状态仅写入浏览器本地数据
